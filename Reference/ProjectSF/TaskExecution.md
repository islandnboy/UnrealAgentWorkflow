# Task Execution

조사, 설계, 코드/문서 수정, 결함 진단과 환경 정비에 사용한다.

1. 요청한 산출물과 완료 기준을 확인한다.
2. 현재 상태와 원인을 필요한 범위에서 조사한다.
3. 다음 행동의 대상·허용 효과·기대 결과를 정하고 필요한 Skill을 읽는다.
4. 실행한 결과를 위험에 맞게 검사한다.
5. 요청한 완료 기준을 충족하면 전달한다. 부족하면 남은 요구사항과 관측 결과를 근거로 다음 행동을 정하고 3–4를 이어간다. 다음 행동을 설명하는 것만으로 실행을 종료하지 않는다.

분석·설계·수정·검증을 항상 별도 Stage나 담당자로 나누지 않는다. 조사 요청은 설명으로, 설계 요청은 설계 Artifact로 끝날 수 있다. 설계나 진단이 쓰기 권한을 암묵적으로 만들지 않는다. 단순 문서 수정에는 전문 Skill과 제품 빌드가 필수가 아니다.

기술적인 반복 검증은 Agent가 이어간다. 진행 보고·사용자 입력·종료는 [ExecutionObservability](ExecutionObservability.md)의 기준으로 구분한다. 결과를 바꾸는 미확정 제품 판단이나 범위를 넘는 변경에서만 사용자 결정을 요청하고, 권한·환경·도구의 실제 차단은 근거와 필요한 조치를 알린다.

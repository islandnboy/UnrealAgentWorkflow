## 갱신한 사실

- 팀원 계정별 플러그인 제작·배포를 남은 과제로 두던 README·사례·구현 현황을 정정했습니다. 공통 서버 MCP를 사용하며 계정별 허용 범위·작성자 귀속은 유지합니다.
- 서버 MCP 조회·저장·readback과 새 대화 복원 근거, 승인된 두 계정의 Android 사용자 확인을 연결했습니다. 사용자 확인과 Codex의 직접 관찰 범위는 구분합니다.
- Spec94의 승인된 여섯 항목 완료, AI 근거 정합성 PASS, 사용자 수락, 매뉴얼, 정식 VERIFY를 반영했습니다. iOS 보류, 원격 main 확인 대기와 CURRENT 미발행을 유지했습니다.
- 첫 재개 요약이 최신 결정을 놓친 뒤 필요한 기록 페이지를 끝까지 읽고 정정한 관측을 남겼습니다. 무인 단발 요약 정확성을 보장하지 않습니다.
- 이전 기술 검토의 국소 회귀·production build PASS와 전체 TypeScript 기존 오류3건 FAIL을 함께 보존합니다. 이번 문서 검수는 해당 테스트 재실행이 아닙니다.

## 공개 범위와 보존

SF Team Hub 실제 화면과 해당 Spec 일부는 사용자 승인에 따라 선별했습니다. 인증정보·계정 권한 설정·개인 채팅 URL·원본 작업 기록 전체와 비공개 게임 코드는 복사하지 않았습니다. 원본 화면에 없는 상태나 완료 표시를 합성하지 않았습니다.

원본 복사 Reference 네 문서와 과거 게임·RPCNet·DataForge 검증 수치를 보존합니다. 서로 다른 checkpoint의 검사 숫자를 합산하지 않습니다. PDF의 원격 기준 SHA는 작성 당시 확인값이며 이 공개 문서 커밋이 제품 구현이나 Spec 발행을 대신하지 않습니다.

공개된 파일별 바이트·SHA-256은 [첨부 자료 목록](../CaseStudies/TeamHubProduction/ArtifactManifest.json)에서 확인할 수 있습니다.

PDF의 주제를 Agent Workflow 시스템 구현으로 맞췄습니다. 추상적인 소개와 직무·경력 서술 대신 계획 검증, capability binding, 공통 서버 MCP 인증과 권한, 조건부 저장과 명령 재전송, 비동기 job lease, Evidence 검증, Unreal mutation 복구를 코드 계약과 실제 화면으로 설명합니다. DataForge는 Workflow가 사용하는 도메인 제작 도구 사례로 포함했습니다. 12페이지이며 기존 사이트 공정 화면과 상세 문서는 보존합니다. 구현 범위와 미완료 기능, 과거 검증 결과의 경계도 유지합니다.

## 개발 과정 중심의 구성 수정

개발자가 설명한 실제 발전 순서에 맞춰 9페이지로 수정했습니다. GPT 리모트의 원격 개발 실험, 컨텍스트 유지 문제와 이슈 기반 레시피 도입, 사이트를 활용한 플랜·설계·구현 분할을 연결했습니다. 도로 제작 #54는 이슈·레시피 방식의 적용 사례, SF Team Hub SPEC-74 R3는 사이트 파이프라인의 적용 사례로 구분했습니다. 최초 리모트 실험에 후대 제작 화면을 소급하지 않습니다. 현재 공정 화면의 SPEC-94와 과거 SPEC-74의 검증 수치는 별도로 표시했고, 추론 성능 향상은 개선 목적으로 표현했습니다. 이전 구성 변경 기록은 이력으로 유지합니다.

사이트 파이프라인의 대표 사례를 SPEC-75 어빌리티 시스템 구조개선으로 구성했습니다. 공통 서버 MCP의 실제 조회에서 Store288 / R3 / 확정 플랜v4 / 설계v6, 설계 논점8개 합의, 구현18개 완료와 검증19개 사람PASS를 대조했습니다. AI는18개PASS·실제 플레이 수락1개PENDING임을 분리했습니다. 2026-10-18 CURRENT R3와 원격main 포함 기록을 확인했습니다. PDF6·7페이지와 결론, 별도 사례 문서에 선별 내용을 반영하고 실제 당시 Teyvat PIE 화면을 추가했습니다. 월드 제작 사례와 기존 허브 운영 사례 문서는 보존합니다.
